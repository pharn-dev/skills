## Deviation from the plan (for review)

The plan passed `signal` to `createReadStream`. Measured this run: on a FIFO whose writer stays open and silent,
destroying the stream does not settle its iterator until the blocked read returns, so the manifest was written only
after the writer closed. `fileEvents` instead races the wait for the next line against the abort signal and does
not pass the signal to the stream; the manifest is now written within about a second of the signal. The process
still exits only when the FIFO writer closes (or on a second signal), as the plan's Risks section said. `commands.mjs`
also types `token` as `string | undefined`, which `tsc` required once closures captured it.
